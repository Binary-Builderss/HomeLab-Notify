Quiet alerts for your homelab.

Homelab Notify watches one Ubuntu server and tells you on Telegram when something needs you: a container that stopped, a disk filling up, a burst of SSH login failures, pending updates. One problem, one message. It only reads, never touches.

In development · iPhone app coming to the App Store

What it watches

Sensible defaults out of the box, every threshold editable from the dashboard or the app.

Docker containers

Only the containers you select. Not running or unhealthy for 30 seconds opens an incident; it closes when the container is back.

Disk space

Measured on the host, not inside a container. Below 10% free for 5 minutes is critical. Missing data is reported as unknown, never as healthy.

SSH login failures

Five failures from one address in two minutes raise one warning per address, with a cooldown so a scan does not flood you.

Ubuntu updates

A daily digest at 09:00 when packages are pending. It reads the local APT cache and never runs apt update.

The agent itself

If the host agent stops reporting for three minutes, you hear about it.

Quiet hours and maintenance

Night hours hold minor notices; critical ones still arrive. Maintenance windows record incidents without notifying.

How it works

Everything runs on your server. No cloud service, no account, nothing sent to us.

Agent on the host

A small Go service under systemd reads Docker, disk, the SSH journal and the APT cache, and reports to the server over loopback only.

Server in Docker

A Go API with SQLite turns observations into deduplicated incidents and keeps a durable outbox, so no notification is lost across restarts.

You

Messages on Telegram, a web dashboard to manage rules and targets, and an iPhone app paired with a one-time QR code.

Read-only by design

Homelab Notify reads and notifies. It cannot be asked to change your server, so it cannot be tricked into it.

  • Restart or stop containers
  • Install updates or run apt
  • Ban addresses or change the firewall
  • Change SSH or service configuration
  • Open a shell or run commands
  • Accept commands from the network

The iPhone app

Open incidents, acknowledge them, choose which containers to watch, tune rules and plan maintenance. It talks only to your server, and a built-in demo lets you try every screen without one.

What you need

  • One Ubuntu server with Docker Compose (tested on Ubuntu 26.04).
  • A Telegram bot for notifications. An existing bot keeps working: Homelab Notify only sends.
  • For the iPhone app: the dashboard reachable over HTTPS with a trusted certificate, for example through Tailscale Serve. iOS 17 or later.

Support

To pair the iPhone app, open the server dashboard, go to Devices → Pair an iPhone, scan the QR code with the iPhone camera and approve the device in the dashboard. The pairing code works once and expires after two minutes.

If the app shows an offline copy, the server could not be reached: check that the HTTPS address opens in Safari on the same iPhone.
